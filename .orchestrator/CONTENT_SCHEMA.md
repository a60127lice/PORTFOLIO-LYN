# Content Schema

All final project facts must be supplied by the user. The initial content is intentionally placeholder-only.

## Project fields

- `slug`
- `title`
- `type`
- `location`
- `year`
- `role`
- `scope`
- `description`
- `challenge` (optional)
- `context` (optional)
- `designResponse` (optional)
- `myContribution` (optional)
- `teamContribution` (optional)
- `process` (optional)
- `development` (optional)
- `materials` (optional)
- `finalDesign` (optional)
- `outcome` (optional)
- `images` with `src`, `alt`, `caption`, and `kind`

## Placeholder rules

- Use `[PROJECT TITLE]`, `[PROJECT TYPE]`, `[LOCATION]`, `[YEAR]`, `[MY ROLE]`, and `[PROJECT DESCRIPTION]` until real content arrives.
- Image placeholders must be visibly intentional and must not resemble finished project photography.
- Optional sections render only when content exists.
- Do not infer clients, employers, responsibilities, outcomes, or qualifications.

## User content checklist per project

1. Project title, type, location, year, role, and scope.
2. Project brief, challenge, and design response.
3. Personal contribution versus team contribution.
4. Selected process, plans, sections, material studies, and final images.
5. Captions, credits, image rights, and preferred image focal points.
6. Outcome, reflection, and next-project order.
